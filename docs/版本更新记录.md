# HomDeck 版本更新记录

> 倒序排列。每次发版：bump `app/config.py` 的 VERSION、写本文件、同步到 .21 验证。

## v0.8.1 — 图标改名 + 按使用次数排序

**动机**：v0.8.0 去重之后，图标名更难认了——`e20c482d60b5c78a78752cf954967d5e.ico`、
`auto-192.168.11.3:8123` 这种自动起的名字，去重让 4 个来源塌成一张图，来源信息反而丢了。
名字是图标库里唯一的语义标签，得让人能改。

### 改动
- **行内改名**：点图标名字变输入框，Enter / 失焦保存，Esc 放弃。走
  `PATCH /api/admin/icons/{id}`，服务端折叠空白、截 80 字、拒空名，写审计 `icon.rename`。
- **按使用次数排序**：`ORDER BY used DESC, id DESC`。用得多的排前面，孤儿图沉到后面。
- 未被任何卡片使用的图标标一个淡色「未使用」——清理时的直接靶子。

## v0.8.0 — 图标库按内容去重

**动机**：图标库里出现了同一张图存好几条。4 台 NAS 跑的是同一套系统、默认图标字节完全一样，
却各占一条；同一个服务抓两次也会多一条。结果是选图标时要在一堆一模一样的小图里挑，
删的时候还得先确认"这两条是不是同一张"。

### 机制
- `icon` 表加 `sha` 列，存**转码后 webp 的 sha256**，配一个唯一索引（`NULL` 不参与）。
- `save_icon` 改成先转码到内存、算 sha、查库：命中已有记录就直接返回那条，
  不写新文件、不建新记录。所以下面三种情况现在都只有一条：
  - 上传同一张图（换个文件名也一样）
  - 从同一站点连抓两次
  - 多台设备用同一套系统图标
- 去重键放在"转码后"而不是"原始字节"上：同一个图标可能是 `.ico`、`.png`、`.jpg`，
  转成 webp 后字节才一致，这才是真正"看起来一样"的判据。

### 迁移（启动时自动跑，幂等）
1. 老库补 `sha` 列；
2. 逐条读文件、算 sha、回填；
3. 发现内容相同的，合并到最早那条：把所有 `item.icon` 改指向保留的那条，删掉多余记录和文件。
4. 实测这批数据：25 条 → 21 条（合并 4 条重复），4 台 NAS 现在共用一张图标，
   所有卡片的图标引用都重新指向过了，无 404。

### 界面
- 图标库每个格子显示「被 N 张卡片使用」，删之前能看清影响面（4 台 NAS 那张显示"被 4 张卡片使用"）。
- 抓图标 / 上传图标命中去重时，状态提示「图标库里已有这张，直接复用」。

### 踩坑
- 唯一索引一开始写在 `schema.sql` 里，老库启动直接 `sqlite3.OperationalError: no such column: sha`
  —— `CREATE TABLE IF NOT EXISTS` 对已存在的表是空操作，索引语句却照样执行。
  索引必须挪到 `_migrate()` 里、`ALTER TABLE` 之后建。

## v0.7.0 — 卡片图标「从网址一键获取」

**动机**：之前加卡片，图标只能手填 emoji 或者先去截图存成文件再上传。
用户的原话是"能不能给个网址就自己把图标抓过来"——这是最省事的一条路径，
顺手把整件事做成"填完内网地址停手，图标自己就来了"。

### 交互
- 新增/编辑卡片对话框里，「图标」输入框下面多了一条工具条：
  `⤓ 从网址获取` 按钮 + 32px 实时预览 + 一行状态。
- **新增卡片时零点击**：内网地址填完停手 900ms 自动抓一次；
  手动改过图标字段后就不再自动覆盖（`dataset.auto` 标记）。
- 编辑老卡片不自动抓，只在点按钮时抓——不擅自换掉用户选过的图标。
- 抓成功 → 图标字段自动填 `/i/xxx.webp`，预览立刻显示，
  状态变绿显示「已从 192.168.1.10:8090 取到 3 KB」；失败→红色显示原因。
- 内网地址为空时回落到外网地址；两者都空提示"先填内网或外网地址"。

### 后端
- 新增 `app/services/favicon.py`（纯标准库 urllib，不引依赖），候选顺序：
  `apple-touch-icon` → 最大的 `rel=icon`（按 sizes 排）→ `og:image`/`twitter:image` → `/favicon.ico`。
- 新接口 `POST /api/admin/icon-from-url`，管理员 + 20 次/分钟限流，
  抓到后走 `uploads.save_icon` 统一转 160px webp 进图标库，返 `/i/xxx.webp`。
- **刻意允许私有地址**：192.168/10/172.16 正是要抓的对象，不做 SSRF 白名单
  （能调这个接口的本来就是管理员，滥用面等于他自己的权限）。
- 内网自签 HTTPS 关掉证书校验，只读图片，风险可接受。

### 踩到的两个坑（已修）
- **百度首页 1.2 MB**，原来 `MAX_HTML = 512 KB` 直接判"响应太大"失败。
  改成"HTML 只读前 512 KB 并截断解析"——图标声明都在 `<head>` 里，后面的正文没用。
- **自家 `/favicon.ico` 返回的是 SVG**，Pillow 解不了会报"抓到了但用不了"。
  改成 `image/svg+xml` 直接判为"不是可用图片"，继续找下一个候选
  （多数站点同时提供 png 的 apple-touch-icon）。

### 验证（真机 .21 上跑）
| 目标 | 结果 |
|---|---|
| 内网 `http://192.168.1.10:8090` | 3.0 KB，取自 PWA 的 192 图标 |
| `https://www.baidu.com` | 8.4 KB，head 解析成功 |
| `https://github.com` | 8.7 KB ← images.ctfassets.net |
| `http://127.0.0.1:8000`（本站，只有 svg） | 预期失败，提示"都取不到"，不再误报成功 |
- 前端实测：新增卡片 → 填内网地址 → 900ms 后图标字段自动变成 `/i/xxx.webp`，
  状态「已从 192.168.1.10:8090 取到 3 KB」（绿），预览已渲染。
  保存落库核对通过，测试卡片与 4 张测试图标已清理干净。

## v0.6.0 — 搜索框支持切换「本站 / 百度 / 谷歌」

**动机**：v0.5.0 的搜索框只能过滤本页面板。Sun-Panel 把「搜哪儿」藏在设置里，
但 40+ 用户不会去设置页找一个开关——所以直接把范围选择摆进搜索框。

### 交互
- 搜索框左侧新增引擎按钮：`本站` / `百度` / `谷歌`，点击展开下拉（玻璃菜单，选中项打勾 + 一行说明）。
- **本站**：输入即时过滤卡片（原行为不变），`Enter` 跳第一张可见卡，`↑` 回搜索框。
- **百度 / 谷歌**：输入不再过滤本地（输入框里是要送出去的词，不是筛选条件），
  `Enter` 直接新标签打开搜索结果；右侧计数变成 `⏎ 百度` 的提示。
- **本站模式下 `Ctrl/⌘+Enter`**：等于「这个词去百度搜」，不用先切引擎。
- 选择存 `localStorage.homedeck.engine`，下次进来还是上次那个。
- `Esc` 先关菜单、再清空输入；点菜单外任意处关闭；菜单项可 Tab + Enter 选择。

### 实现
- 引擎表集中在 `panel.js` 顶部的 `ENGINES` 数组（id / 名称 / placeholder / URL 前缀），
  加 Bing、DuckDuckGo、自定义 URL 只需加一行。
- 查询词一律 `encodeURIComponent`，中文实测：`homelab 交换机` →
  `https://www.baidu.com/s?wd=homelab%20%E4%BA%A4%E6%8D%A2%E6%9C%BA`。
- 修了一个连带 bug：`.search-count` 在绝对定位下缺 `top:50%`，会贴在框顶（现居中，y=171，框 154–200）。

### 验证
- 三种模式 Enter 的 URL 全部抓取核对（拦截 `window.open` 断言）：
  百度 / 谷歌 / 本站+Ctrl 回落百度，三条都对。
- 本站过滤未受影响：`nas` → 4/23（4 台名字含 NAS 的机器）。
- 刷新后引擎选择保留（baidu）。

## v0.5.0 — 首页改按 Sun-Panel 的语言做（壁纸 + 玻璃 + 居中头部）

**判断**：v0.4.0 把「机架面板」的语言补齐了，但用户要的是 Sun-Panel 的那种首页观感。
两套语言不兼容——机架语言靠「石墨底 + 边缘 + 键位」，Sun-Panel 靠「壁纸 + 半透明玻璃 + 光晕」。
这一版按后者重做首页，**保留**自家的三样东西：分组机位序号（信息）、等宽数字、可达性底线
（焦点环、目标尺寸、40+ 字号、reduced-motion）。管理台不动。

### 结构
- 去掉面板顶栏，换成「壁纸舞台」：`.stage-wall`（三束色光 + 深底 + 64px 极细网格 + SVG 噪点）、
  `.stage-mask`（上下两道暗角，等价于 Sun-Panel 的「背景遮罩」）。
- 头部居中：站点图标 + 站点名（`clamp(26px,3vw,40px)`/700）+ `|` 分隔符 + 实时时钟（等宽 300，
  5s 刷新，hover 显示中文长日期），下面一条 560×46 的玻璃胶囊搜索框。
- 管理/登录/WAN 收进右上两枚玻璃胶囊（`.dock`）；WAN 改成「红点 + WAN」的告警胶囊，
  手机端也不隐藏。
- 分组：组间距 **44px**，标题 **20px/800** 白字（Sun-Panel 的 `text-xl font-extrabold`），
  带文字阴影；机位序号改成半透明小字，信号条保留并发绿光。
- 卡片改成 Sun-Panel 的 **icon 模式**：玻璃只包图标（76×76 圆角 20，图标 44/52），
  标题落在玻璃外的下方（13px 白字 + 阴影）。网格 `minmax(120px,1fr)` gap 18 →
  1440 下 **8 列 × 136px**，23 个入口 4 行、1440×900 一屏装完不滚动。
- 悬停用 Sun-Panel 同款三层光晕：同色扩散 18px + 1px 亮边 + 黑色 22px 扩散；
  `:active` 轻微 `scale(.97)` + 内阴影做按下感。

### 取舍记录
- **不引外链壁纸**。Sun-Panel 用照片 + blur，HomDeck 零外链、夜间为主，所以用 CSS 合成"夜窗"
  （三束色光 + 噪点），`--wall-*` 四个变量可整体替换成真实图片，DOM 不用动。
- **描述不进卡片**。icon 模式下没有描述位（Sun-Panel 是 info 模式才有），描述仍在 `title` 属性里。
  要把描述显示出来，得加一个「info 模式」开关，留到下一版。
- **壁纸底不再是纯石墨**，`body::before` 那层旧网格加了 `:not(.on-stage)` 限定，避免两层网格叠成噪声。
- 实测对比（截图取像素算的）：玻璃键对页面底 **1.46:1**、搜索框 **1.17:1**，都在"半透明层"该有的区间；
  键上文字对底 **17.3:1**、分组标题 **14.6:1**、头部标题 **17.9:1**。

## v0.4.0 — 兑现「机位」的物理性（设计评审落地）

**结论**：v0.3.0 的方向站得住，但执行把「机位」的物理性删掉了——卡片靠 1.05:1 的亮度差存在，
hover 只有 1.078:1，图标字形实际 22px，卡片尺寸浪费了纵向 250px 预算。v0.4.0 不换方向，
把「有边缘 / 按下有反馈 / 图标主导 / 序号章节化」四条兑现，全部按数值规格落地。

### P0（破坏任务或违反自定规则）
- 深色卡片补边缘：`--card-line: rgba(255,255,255,.075)`（合成 ≈ `#24292f`，对页面底 1.33:1）；
  悬停面 `--card-hover: #1f262e`（1.21:1，原 1.078:1 等于不可见）。
- 浅色改机制：卡片线独立成 `#dde3ea`（原 `rgba(18,22,28,.06)` 叠白卡 ≈ 1.01:1），
  悬停不再用更暗的 `--surface-2`（原来悬停是向下沉），改为边框提亮 + 微投影。
- 新增 `--line-ctl`（深 `#5d646d` / 浅 `#8a939d`），搜索框、表单控件边框达 WCAG 1.4.11 的 3:1。
- 图标字形放大：盒子 32 → **48px**，emoji `font-size` 22 → **40px**（原来只占盒子 69%）；
  无图标时的首字母键帽同步从 `--fs-4` 提到 `--fs-5`。
- 手机端不再隐藏 `WAN`：缩成 18px 状态点（`--danger` 圆点，`title` 保留说明）——
  手机 + 蜂窝是唯一会出现 WAN 的场景，原来最该看警告的设备上看不到。
- 管理台行操作常显：`.gops` `opacity 0 → .55`，hover / `:focus-within` → 1；
  `.icon-btn` 24 → **32px**，按钮间距 1 → **4px**，行 padding → **10px**（键盘用户可触及）。

### P1（削弱体验）
- 字号整体 +1 档：`--fs-1 12 / 2:13 / 3:15 / 4:17 / 5:20 / 6:26 / 7:32`；
  卡名 15 → **17/1.3**，描述 12/1.4，页脚 12。
- 悬停去掉 `translateY(-2px)` 与投影（与「不浮起」自相矛盾，且 2px 缝里位移会互相挤动）；
  改为背景受光 + 边框提亮 + `--card-hover-shadow` 顶面高光；`:active` 用 inset 投影做按下感。
- 网格 `gap 8 → 12`，卡 padding `18/12/14`，列宽 `minmax(116px) → minmax(184px)`
  ——1440 宽下实测 **6 列 × 192.7px**，23 个入口从「4 行 114px」变成「4 行 132px」仍一屏装完（scroller 高 900）。
- 分组节奏：`.group` 32 → **40px**（对 gap 12 = 3.3×），`.group-title` margin 14px，`.wrap` padding 32。
- 分组头重做：机位序号（等宽 `01`，随拖拽变化，是信息不是装饰）+ 3px 信号块 + sans 分组名 + 规则线 + 计数胶囊。
- 搜索框固定 260×40，去掉 `width 232→300` 的聚焦跳宽（会带动整行横移 68px），聚焦改为底部 2px 强调线。
- 焦点环统一：全局与控件一律 `outline: 2px solid var(--ring)`，不再有 `outline:none` + 1px 变色。
- 删掉入场 stagger（原来到第 13 张才封顶，全亮需 388ms）：单张 160ms 纯透明度淡入。

### P2（打磨）
- 计数胶囊 3×6 → **4×8**，`tabular-nums`；页脚加 `env(safe-area-inset-bottom)`。
- 空状态键位 44 → **56px**；登录卡 340 → 360px（与文档一致）。
- 卡片内容垂直居中（`justify-content: center`），修掉有/无描述时图标上下不对称。
- 手机端 tabs 加右缘渐隐，暗示可横滚；网格 `minmax(140px)` 保 2 列，图标 44px。

## v0.3.0 — 视觉重做（机架面板方向）

**方向**：仪表盘 / instrument panel。冷石墨底 + 单一信号绿 + 等宽字体做标签与数字，
卡片做成无边框「键位」而非浮起的白盒子。目标是一屏扫完所有入口，不做营销留白。

### 设计 token 三层化
- 原始层（`--ink-*`、`--green-500`、`--red-500`、`--mono`）→ 语义层（`--bg`、`--surface`、
  `--line`、`--fg`、`--fg-dim`、`--fg-faint`、`--accent`）→ 组件别名（`--radius`、`--bg-card`、
  `--bg-soft`、`--shadow-lift`、`--accent-soft`，兼容管理台旧变量名）。
- 字号从 16 档收敛到 6 档（`--fs-1` 11 / `--fs-2` 12 / `--fs-3` 13.5 / `--fs-4` 15 / `--fs-5` 18 / `--fs-6` 22）。
- 圆角从 13 种收敛到 2 族（`--r-1` 6 / `--r-2` 10 / `--r-pill`）。
- 十六进制字面量从 19 个降到 3 个，其余全部走 token。
- 阴影 2 档（`--sh-1` / `--sh-2`），动效统一 `--ease` + 120/220ms。

### 视觉改动
